Run `fleet --help` to see the summary in your terminal, or pass `--json` to commands like `list`, `inspect`, `logs`, `gate`, `phone`, and `doctor` for structured agent output.

## Setup and daemon

```sh
fleet setup --install
fleet setup --join computer-invite.json --install
fleet setup --local
fleet daemon
fleet doctor
fleet --version
fleet --help
```

- `fleet setup --install` prepares certificates, system trust, and background startup on your gateway.
- `fleet setup --join FILE --install` enrolls a secondary checkout computer using a gateway invitation.
- `fleet setup --local` configures Fleet on `127.0.0.1` without Tailscale for local testing.
- `fleet daemon` runs Fleet in the foreground (don't run it alongside the installed background service).
- `fleet doctor` checks Tailscale, the local daemon, and `gate.fleet` DNS resolution.

## Creating and managing apps

```sh
fleet init notes
fleet init --name notes
fleet register /path/to/existing-app
fleet unregister notes
```

- `fleet init DIR` creates a new app folder with starter client, server, types, and `AGENTS.md`, then registers it.
- `fleet init --name NAME` initializes an app in the current directory without overwriting existing source files.
- `fleet register DIR` registers an existing Fleet app checkout.
- `fleet unregister NAME` removes the app's route while preserving its source files and database. The name remains bound to its original app ID so a browser origin isn't silently reused by a different app.

## Opening and inspecting apps

```sh
fleet open [NAME]
fleet list --json
fleet inspect NAME
fleet logs NAME
```

- `fleet open [NAME]` (run on the gateway) signs your local browser in through Fleet Gate and opens the app — or opens your app index at `https://gate.fleet` if no name is given.
- `fleet list --json` returns all registered apps and their build/worker status.
- `fleet inspect NAME` shows build revision, exported queries/mutations/jobs, and scheduled job state.
- `fleet logs NAME` prints the last 100 lines of build output, server `ctx.log` messages, and browser client errors.

## Calling operations from the CLI

```sh
fleet call notes queries notes
fleet call notes mutations addNote '{"text":"Hello from the CLI"}'
fleet call notes jobs dailyCheck
```

The syntax is `fleet call APP queries|mutations|jobs OPERATION [JSON]`. Operations run as the owner on the app's checkout computer.

## Backups and restores

```sh
fleet backup notes --output notes.sqlite
fleet restore notes notes.sqlite
```

`backup` takes a consistent SQLite snapshot while Fleet is running. `restore` requires Fleet to be stopped first and saves a copy of the previous database before replacing it. Run both on the checkout computer. See [data and jobs](/docs/data-and-jobs#back-up-and-restore).

## Fleet Gate and iPhone setup

Run these on the gateway:

```sh
fleet gate
fleet gate --noopen
fleet gate reset
fleet phone
fleet phone off
fleet profile --output fleet.mobileconfig
```

- `fleet gate` prints a 10-minute device sign-in code and opens `https://gate.fleet` (skip the browser with `--noopen`).
- `fleet gate reset` revokes all active browser sessions immediately.
- `fleet phone` opens a temporary private setup link over Tailscale Serve and prints a QR code for Safari.
- `fleet phone off` manually removes the temporary phone setup route if you didn't finish setup.
- `fleet profile --output FILE` exports your installation's public root certificate profile (never its signing key).

## Enrolling another computer

```sh
fleet invite --output computer-invite.json
```

Run on the gateway to generate a single-use, 10-minute enrollment file for a second computer. See [multiple computers](/docs/computers).

## Removing Fleet

```sh
fleet uninstall
```

Stops the background service and removes local startup files and computer certificate trust while keeping your app checkouts and SQLite databases intact. See [removing Fleet](/docs/troubleshooting#remove-fleet).
