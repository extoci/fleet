Fleet uses your existing Tailscale network for private connectivity. It adds app routing, `.fleet` names, HTTPS, and Gate sign-in. It does not configure public app hosting or require an exit node.

## One gateway, local checkouts

Your first Fleet computer acts as the gateway. It serves DNS, HTTPS, and Gate. Apps and their data stay on their checkout computers; the gateway routes requests to those computers over Tailscale.

For an app to open, the gateway and its checkout host must be awake and connected. Adding another computer does not automatically move any app or data. See [multiple computers](/docs/computers).

## Restricted DNS

Fleet setup prints the exact nameserver address for your gateway. Add that address in [Tailscale DNS settings](https://login.tailscale.com/admin/dns) as a **restricted nameserver** for the suffix **`fleet`**.

Keep all unrelated DNS settings intact. Do not point every DNS query at Fleet. Each client must accept Tailscale DNS settings. If an existing `fleet` mapping points elsewhere, resolve the conflict deliberately rather than overwriting it.

If your devices use an exit node, enable **Use with exit node** on the restricted nameserver. An exit node is otherwise unnecessary. See [Tailscale's DNS documentation](https://tailscale.com/docs/reference/dns-in-tailscale).

The gateway answers registered app names and rejects unknown names. Devices connect to the gateway's private address, not phone loopback. Both UDP and TCP DNS must be reachable on port 53.

## Private HTTPS

Fleet creates a certificate authority for your installation. The private signing key stays on your gateway. Computers and phones trust its public root so browsers can validate names like `notes.fleet`.

This is system certificate trust, not a narrowly scoped app permission. Only install a profile generated by a gateway you own and trust. Never solve a certificate error by disabling verification.

Your phone's one-time certificate setup is separate from sign-in. Fleet Gate still authenticates the owner after HTTPS works.

## Setup URLs versus app URLs

`fleet phone` temporarily uses a private Tailscale Serve HTTPS address ending in `.ts.net` on port 8444. It delivers the setup page using a certificate the phone already trusts.

That longer URL is **only for setup**. Normal apps use `https://APP.fleet`. Fleet does not configure public Funnel, replace unrelated Serve routes, or ask you to route all internet traffic through your computer.

## Check the connection

```sh
fleet doctor
```

Doctor checks Tailscale, the daemon, and system name resolution. It is a useful first diagnostic, not proof that Safari trusts the root or a cellular path works. Continue with [troubleshooting](/docs/troubleshooting) for those cases.
