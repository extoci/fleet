Fleet works with an agent that can edit local files and run commands. It does not require a Fleet-specific coding assistant or a hosted agent subscription.

## Give the agent the app contract

Open the app checkout and ask the agent to read its generated `AGENTS.md`. A useful first request is:

> Read AGENTS.md. Add a search field to this notes app. Keep the existing data format, use Fleet's queries and mutations, and check Fleet's logs after the edit. Do not start a separate dev server.

The agent edits `client/index.tsx`, `client/style.css`, and `server/index.ts`. Fleet owns build watching, app workers, HTTPS, and sign-in.

## Inspect before changing

```sh
fleet list --json
fleet inspect notes
fleet logs notes
```

`list --json` gives machine-readable runtime state. `inspect` adds details for an app, including job state. `logs` shows recent build and runtime output.

Read the existing data contract before changing it. A build succeeding does not prove an old document shape still works.

## Exercise an operation

```sh
fleet call notes queries notes
fleet call notes mutations addNote '{"text":"A note from my agent"}'
```

The mutation writes real app data as the owner. Use a disposable app or make a backup before testing destructive changes. Run these commands on the computer that owns the checkout.

## Verify the edit

1. Inspect the app state and recent logs.
2. Confirm the new build succeeded rather than viewing the fallback build.
3. Open the app and exercise the changed behavior.
4. Confirm existing data still works and new data survives a restart.

Fleet reloads the browser on successful updates. Unsaved form state can be lost. A failed build leaves the last successful build available, which can look like an edit was ignored.

## Protect data and credentials

Before a data format change:

```sh
fleet backup notes --output notes-before-change.sqlite
```

Keep a recoverable copy outside the app host. Do not confuse source control or a last-good build with a data backup. See [backup and restore](/docs/data-and-jobs#back-up-and-restore).

Server credentials belong in `.env.fleet.server`; read them through `ctx.env`. Never give a client component an API key. Do not log secrets while debugging.

## Keep the runtime simple

Do not start Vite, another application server, or a manual publish process for a Fleet app. Do not add a second login system: Fleet Gate already provides the owner identity. Use the [app format](/docs/apps) instead.
